## 产品定位

Coomi Deck 是 Coomi 生态的桌面端，定位**跨设备 agent 协同调度系统**——调度层而非执行层。

- 桌面 CLI agent 工具（zcode、codex 等）作为被管理的**子代理**：注册、读日志/状态、派发任务、规范化回收结果。
- Coomi 引擎内置，是协调者，也直接处理零散任务。
- 用户以架构师视角在控制台统揽全局：看进度、做审批、派任务、收结果。
- 多端协同不经过第三方云：桌面状态同步到手机端 Coomi（随身查看/审批入口），走用户自有基础设施（CoomiLink，方案待定）。
- 价值观：**自动化 > 便携性 > 稳定性**；界面承诺舒适、方便、高效。

### 核心设计哲学

**Coomi 不设计方案。** Coomi 只精确描述"现在的问题"和"要达到的目标"；问题溯源与方案设计交给专业 agent，结果回流 Coomi 再呈给用户。落地到界面语言：

- 所有派发/模板/工作流节点表单只问三件事：问题描述、目标描述、资源与约束——不提供"解决方案步骤"输入位。
- 审批卡片呈现 agent 的方案摘要与依据，而非 Coomi 的二手加工意见。
- 迭代可溯源：每次派发记录所用提示词的版本，每轮迭代留清单。

协议层对齐 **A2A**：任务状态机采用 A2A 生命周期 `submitted → working → input-required → completed / failed / canceled`；`input-required` 即等待审批/输入。代理详情展示 AgentCard（能力、技能、端点）。

## 第 1 轮结论（产品与信息架构）

### 实体模型（8 个，用户面向词汇）

| 实体 | 定义 |
|---|---|
| 工作流 Workflow | 可复用 DAG 配置；节点 = 任务步骤（代理指派、提示词模板、审批门） |
| 任务 Task | 一次执行实例，统一任务流的单元；来源两种：工作流运行 / 单次派发 |
| 步骤 Step | 工作流任务内某节点的单次执行 |
| 代理 Agent | 注册的执行单元；Coomi 引擎为内置特殊代理 |
| 审批 Approval | 决策请求，三类：工作流审批门 / 代理运行时请求 / 资源申请 |
| 产物 Artifact | 任务的结构化产出（文件、报告、diff 摘要），附属任务 |
| 提示词 Prompt | 核心可复用资产。两类：**任务模板**（部署上线、改官网、反馈分析→规划批次……）、**方法论偏好**（讨论性/计划性等，常驻指令，随派发自动注入、单次可停用）。模板含：问题描述、目标描述、默认代理、关联资源、变量槽；有版本历史与使用记录 |
| 资源 Resource | 执行所需资源：服务器、密钥凭证、GPU、API 额度等。挂一份"使用指令"（用户口述用法 → Coomi 精炼为提示词，派发时随附）；带审批策略（人工审 / Coomi 自动放行规则） |

### 导航与布局

- 一级导航 7 项：**控制台 / 任务 / 工作流 / 提示词 / 代理 / 资源 / 设置**
- 三栏骨架：左导航 + 主内容区 + **右侧 Coomi 面板**（VS Code 副侧栏范式：常驻、可折叠、可调宽；编排器等需画幅页面自动收起）
- Coomi 面板 = 用户与 Coomi 的指挥通道：用户在此说话，Coomi 在此汇报（agent 结果回流 → 摘要 → 面板消息 + 必要时生成收件箱卡片）；输入框支持 `@` 引用资源、`#` 引用提示词模板
- 审批收件箱 = 控制台首页第一屏主体；卡片带三类审批类型徽标；资源申请卡支持"本次批准 + 总是放行此类"→ 沉淀自动审批规则

### 关键动线

1. **审批决策**（最高频）：通知 → 控制台收件箱 → 卡片展开上下文 → 批准/拒绝/改参数 → 下一张自动顶上；目标纯键盘 30 秒清空收件箱；手机端同一套卡片
2. **派发任务**：⌘K → 选目标（Coomi/代理/工作流）→ 问题+目标+资源约束 →（工作流给 DAG 预览）→ 启动 → 统一任务流
3. **追踪工作流**：任务详情 DAG 运行态（节点着色=状态）→ 节点级干预（重跑/跳过/终止）→ 完成汇总报告；配套编辑动线：编排器画布拖节点、连线、配节点 → 存版本 → 单节点试运行

### 页面清单（12 个一级页面 + 4 个非页面形态）

控制台、任务流、任务详情（单次=日志+产物 / 工作流=DAG 运行态）、工作流列表、工作流编排器、提示词库、提示词详情/编辑（版本历史+使用记录）、代理列表、代理详情、资源列表、资源详情（使用指令+审批策略）、设置。

非页面形态：⌘K 命令面板、快速派发面板、Coomi 右栏、审批详情抽屉。

## 第 2 轮结论（技术边界）

| # | 议题 | 结论 |
|---|---|---|
| T1 | 代码组织 | 引入 **pnpm workspace**：`coomi-deck/`（顶层）+ `packages/{tokens, protocol}`；apps/web 不强制改造、渐进接入 |
| T2 | 原型策略 | **原型即骨架**：直接在 coomi-deck/ 起 Vue 3 + Vite + Pinia + TS 工程；bridge 接口层第一天就位，原型期挂 demo transport（fixtures + 定时器模拟实时推送），沿用 apps/web 的 transport 模式 |
| T3 | DAG 画布 | **Vue Flow**（@vue-flow/core）；端口级复杂编辑需求出现时再评估 Antv X6 |
| T4 | 组件策略 | **Reka UI（headless 原语）+ 自研样式**；图标 Lucide；长列表 vue-virtual-scroller |
| T5 | 令牌共享 | packages/tokens 以 CSS 自定义属性为唯一源（沿用移动端扁平命名 + 新增桌面语义层）；`data-theme` 双主题、dark 默认；不引 Style Dictionary |
| T6 | 壳预留 | 文件/剪贴板/系统通知走 bridge 抽象；不依赖浏览器专属 API；标题栏等壳决策推迟到视觉轮 |
| T7 | 窗口基线 | 最小可用尺寸 **1280×800** |

## 第 3 轮（进行中）：视觉方向

用户决定不预先单选方向，而是**四套主题全部落地为可运行原型**、在同一套界面上即时切换对比后再拍板：

| 主题 | id | 性格 |
|---|---|---|
| 静塔 | `tower`（默认） | 中性近黑工程控制台，1px 细线分层，极简阴影 |
| 暖墨 | `ink` | 暖调深色书房感，钢青蓝 + 陶土橘，哑光语义色 |
| 舰桥 | `bridge` | 深海军蓝 + 电光蓝/青，点阵纹理与克制辉光 |
| 蓝白 | `paper` | 与 Coomi Android 移动端逐值对齐（#2d61c6 / #d47458 / 16px 卡片 / 药丸按钮 / 软阴影） |

四主题共享的公共地基（已确认）：

- **色彩语义规则：冷蓝 = 机器流转，暖橙 = 人工决策点**——贯穿四套主题
- 正文 13px / 辅助 12px；日志、数字、ID、时间戳等宽 + tabular-nums；4px 基网
- 语义令牌驱动（`data-theme` 切换），圆角/阴影/按钮形态也令牌化（蓝白主题因此呈现移动端的大圆角与药丸按钮，而非仅换色）

原型现状：`coomi-deck/` 已可运行（控制台、任务流、代理、设置、组件样张页 + 右侧 Coomi 面板 + ⌘K），工作流/提示词/资源为占位页，待第 4 轮细化。

### 第 3 轮迭代 1（用户反馈后调整）

- **默认主题 = 蓝白（paper）**——以 Coomi Android 移动端语言为默认，四套主题仍可随时切换对比
- **控制台改为箱庭式两侧布局**：左侧主体 = 运行中的工作流（每张卡片内嵌 DAG 节点状态条 + 进度）与单次任务；右侧主体 = 选中工作流的详情（节点步骤轨、节点级干预、实时日志）+ 待审批清单。点击左列卡片切换右侧详情
- **右侧 Coomi 面板支持横向拖拉调宽**（264–560px，localStorage 持久化，⌘J 收起/展开）
- **品牌资产接入**：LOGO（coomi-agent.png）用于左侧导航品牌位；吉祥物（coomi.png）用于 Coomi 面板头像与收件箱清空空态。两图均为不透明底，统一以白色圆角磁贴形式呈现以兼容四套主题

### 第 3 轮迭代 2（LOGO 修正 + 窄窗口适配）

- **弃用像素吉祥物，全产品统一使用 LOGO**（导航品牌位 / Coomi 面板头像 / 空态插画）
- 修复 LOGO 以原始 975px 溢出渲染的问题：生成 256px 衍生图（logo-256.png，System.Drawing 高质量缩放），`<img>` 标签带硬性 width/height，外层磁贴 overflow 裁切
- 窗口宽度 < 1380px 时 Coomi 面板**默认自动收起**（⌘J 手动唤起），保证 1280×800 下控制台两列不拥挤；详情列 404→380px；滚动条视觉弱化
